# 개발 운영 워크플로

> 목적: 관리자와 가시적 하위 작업의 책임, 단계 게이트, 보고 형식을 정의합니다.
> 읽는 경우: 작업 생성·배정·통합·QA·단계 완료 보고 시.
> 관련 문서: [`../CURRENT_STATUS.md`](../CURRENT_STATUS.md), [`../roadmap/README.md`](../roadmap/README.md), [운영 원문](../archive/ADMIN_MANAGER_GUIDE.original.md)

## 핵심 원칙

- 실제 출시 프로젝트 `SmallWorld`를 단계적으로 개발하며 한 번에 현재 단계 하나만 진행합니다.
- 구현 전에 `White_Happy_Room`에 책임별 가시적 작업을 만들고 수정 범위와 인터페이스를 분리합니다.
- 관리자는 결과를 직접 리뷰·통합하고 Unity 컴파일 오류 0개, 관련 테스트, Windows 빌드, 런타임 스모크, Git 범위를 검증합니다.
- 사용자 승인 전에는 다음 단계 작업을 만들거나 수정하지 않습니다.
- 사용자 변경과 다른 작업의 결과를 임의로 삭제·되돌리지 않습니다.
- 비용 0원, 상업 이용 가능성이 검증된 무료/자체 에셋만 허용하며 등록부에 기록합니다.
- 참고 작품의 캐릭터·대사·장면·퍼즐·UI·코드·고유 시각 디자인을 복제하지 않습니다.

## 하위 작업 지시 필수 항목

담당 기능, 목적, 작업 범위, 수정 가능 파일, 수정 금지 영역, 연결 인터페이스, 완료 조건, 테스트 방법, 결과 보고 형식을 명시합니다.

## 하위 작업 완료 보고

1. 구현 기능
2. 생성·수정 파일
3. 사용 방법
4. 수행한 테스트와 결과
5. 남은 문제
6. 연결할 부분
7. 외부 에셋과 라이선스

## 단계 완료 보고

완료 단계, 구현 기능, 하위 작업별 결과, 통합 파일, 테스트 항목·결과, Console 오류 수, Windows 빌드 결과, 남은 문제, 다음 단계를 보고합니다. 마지막에는 결과 확인과 다음 단계 승인 요청을 포함합니다.
