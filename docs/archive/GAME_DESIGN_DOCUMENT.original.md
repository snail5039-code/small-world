# 둘만의 작은 세계

## 부제: 아무것도 남지 않은 하얀 방

> 전체 게임 기획서(GDD) 초안 1.0

> **제작 핵심 조건: 프로토타입과 버티컬 슬라이스 승인 전까지 엔진·도구·플러그인·에셋 구매비 0원. 유료 구매와 구독은 사용자의 별도 승인 없이는 진행하지 않는다.**

### 한 줄 소개

> 기억을 잃은 플레이어가 화면 속 소녀와 집을 완성하면서, 자신이 가상세계의 합성 인격이라는 진실과 살아 움직이는 집에서 탈출하는 심리 공포 게임.

### 플레이어 판타지

- 나만을 기다리던 소녀와 관계를 쌓는다.
- 평범한 공간의 작은 모순을 스스로 발견한다.
- 조작된 기억과 선택지를 의심하고 진실을 추리한다.
- 모형 집을 바꿔 실제 공간을 움직인다.
- 무기 없이 괴물과 살아 있는 집에서 탈출한다.
- 누구를 믿고 누구의 기억을 구할지 결정한다.

## 2. 기획 목표

### 핵심 목표

밝고 친밀한 연애·생활 게임의 분위기가 플레이어의 행동과 선택을 통해 서서히 심리 공포로 변하는 경험을 만든다.

### 핵심 감정 흐름

```text
호기심 → 친밀감 → 작은 불편함 → 의심 → 배신감
→ 공포 → 연민 → 선택의 죄책감 → 불확실한 해방
```

### 반드시 지킬 세 가지

1. 소녀는 무서운 존재이면서도 끝까지 구하고 싶은 인물이어야 한다.
2. 퍼즐과 공포 연출은 반드시 기억·관계·정체성이라는 이야기와 연결되어야 한다.
3. 플레이어의 선택은 수치만 바꾸는 것이 아니라 대사, 공간, 구출 인원과 엔딩에 흔적을 남겨야 한다.

### 피해야 할 방향

- 이유 없는 점프 스케어 반복
- 걷기만 하고 상호작용이 거의 없는 진행
- 애니메이션 캐릭터의 외형에만 의존한 홍보
- 다른 심리 공포 게임의 캐릭터·장면·퍼즐 복제
- 설명문으로 모든 반전을 한꺼번에 공개
- 선택과 무관하게 완전히 동일한 결과만 제공
- 실제 개인정보나 운영체제 파일을 이용하는 공포 연출

## 3. 참고 방향과 독자성

### 참고 게임

| 게임 | 참고할 부분 | 우리 게임에 적용하는 방식 | 복제하지 않을 부분 |
| --- | --- | --- | --- |
| MiSide | 밝은 캐릭터 게임에서 심리 공포로 전환되는 대비, 캐릭터와 공간의 친밀감 | 집 꾸미기와 대화를 통해 소녀에게 정을 붙인 뒤 모형 집과 기억 공간으로 분위기 전환 | 캐릭터 외형, 연애 설정, 장면 구성, 대사, 추격과 퍼즐을 그대로 사용하지 않음 |
| Doki Doki Literature Club! | UI와 대화 형식을 이용한 메타 공포, 친밀한 캐릭터에 대한 불신 | 선택지·자막·저장 화면을 외부 존재가 조작 | 학교·동아리 설정, 캐릭터 관계, 직접적인 파일 조작 연출을 복제하지 않음 |

| Inscryption | 하나의 방, 게임 규칙과 이야기 반전을 결합한 구조 | 모형 집을 퍼즐 도구·진행도·기억 저장소로 동시에 사용 | 카드게임 규칙, 오두막, 캐릭터와 시각 연출 복제 금지 |
| SOMA | 복제된 의식과 인간 정체성에 대한 질문 | 주인공이 개발자와 희생자의 합성 인격이라는 갈등 | 해저 시설, 생명체 디자인, 구체적 사건 전개 복제 금지 |
| P.T. | 반복되는 공간에서 작은 차이를 발견하는 긴장 | 집 구간에 반복마다 달라지는 소품·대사·시간 단서 배치 | 동일한 복도 구조, 욕실·라디오·반복 장면 재현 금지 |

참고 게임은 완성된 작품을 분석하기 위한 기준이며, 콘텐츠를 조합해 복제하기 위한 목록이 아니다. 새로운 장면을 설계할 때는 “어느 게임과 닮았는가?”보다 “모형 집, 기억 가구, 미래의 소녀라는 우리 규칙으로만 가능한가?”를 먼저 검토한다.

### 참고 요소 적용 기준

1. 참고 게임의 구체적인 캐릭터·대사·공간 배치·퍼즐 해법은 가져오지 않는다.
2. 장르적 감각을 참고하더라도 우리 세계관 규칙으로 원인과 결과를 다시 설계한다.
3. 한 장면이 특정 참고작 하나로 바로 설명되면 재설계한다.
4. 모형 집이나 기억 복원 시스템과 연결되지 않는 공포 장치는 우선 제외한다.
5. 공개 전 유사성 검토를 통해 캐릭터 실루엣, 대표 장면과 마케팅 문구를 비교한다.

### 참고할 장르 감각

- 밝은 캐릭터 게임에서 심리 공포로 전환되는 대비
- 집과 일상 공간이 낯설게 변하는 연출
- 관계가 쌓인 캐릭터를 의심해야 하는 감정적 갈등
- 짧은 탐색·퍼즐·추격을 교차하는 진행 속도
- 선택지, 저장 화면, 자막을 활용하는 메타 공포

### 작품의 독자적 요소

- 모형 집과 실제 공간의 동기화
- 희생자의 기억이 담긴 가구
- 기억을 보존하면 길이 막히고 파괴하면 탈출이 쉬워지는 갈등
- 과거의 소녀와 미래의 관리 AI가 같은 존재라는 구조
- 이름이 프로젝트명이자 방화벽 종료 명령인 퍼즐
- 사망을 반복할수록 이전 주인공의 흔적이 쌓이는 시스템
- 기억과 인격을 나누어 희생자를 복원하는 진엔딩

## 4. 대상 플레이어

### 핵심 타깃

- 스토리 중심 인디 공포를 좋아하는 PC 플레이어
- 캐릭터 관계와 반전을 중요하게 보는 플레이어
- 복잡한 전투보다 탐색과 퍼즐을 선호하는 플레이어
- 스트리밍과 영상으로 반응하기 좋은 장면을 찾는 콘텐츠 제작자

### 예상 플레이 성향

| 성향 | 기대 경험 |
| --- | --- |
| 이야기 탐색형 | 기록과 대사를 모아 세계관 해석 |
| 캐릭터 몰입형 | 소녀의 감정과 관계 변화 관찰 |
| 퍼즐 해결형 | 기억과 공간 규칙을 조합해 탈출 |
| 수집·완주형 | 이름 조각, 가구, 사망 기록, 모든 엔딩 발견 |
| 방송 시청형 | 선택지 조작, 반전, 추격과 사망 장면 공유 |

### 난이도 목표

- 기본 조작은 게임 초보자도 5분 안에 이해할 수 있어야 한다.
- 퍼즐은 평균 5~10분 안에 규칙을 파악하도록 설계한다.
- 추격 난이도는 중간 수준이며 접근성 옵션으로 완화할 수 있다.
- 진엔딩은 행동과 단서 연결이 필요하지만 공략 없이도 추론 가능해야 한다.

## 5. 핵심 게임플레이 루프

```text
집에서 소녀와 대화
  ↓
새로운 가구·문·이상 현상 조사
  ↓
모형 집을 통해 기억 공간 진입
  ↓
환경 탐색과 기억 퍼즐 해결
  ↓
희생자의 기억을 복원·변형·파괴
  ↓
괴물 또는 붕괴 공간에서 탈출
  ↓
가구·이름 조각·기억 기록 획득
  ↓
집 꾸미기와 관계 선택
  ↓
다음 봉인과 장 해금
```

### 한 루프의 권장 길이

- 집 탐색·대화: 5~10분
- 기억 공간 탐색·퍼즐: 20~30분
- 위기·추격: 3~5분
- 결과 선택·집 변화: 5분

## 7. 주요 시스템

### 7.1 조사

- 조사 가능한 물건을 바라보면 작은 아이콘이 표시된다.
- 물건을 들어 회전·확대하고 숨겨진 글자나 흠집을 찾는다.
- 같은 물건을 반복 조사하면 최대 세 단계의 추가 반응이 나온다.
- 소녀에게 물건을 보여주면 애정·경계와 대사가 달라진다.
- 중요한 단서는 기억 기록에 저장된다.

### 7.2 대화와 선택

| 선택 유형 | 기능 |
| --- | --- |
| 감정 선택 | 소녀와의 애정·경계 변화 |
| 행동 선택 | 물건 사용과 공간 변화 |
| 침묵 | 선택하지 않는 행동 자체가 반응을 만듦 |
| 숨겨진 선택 | 특정 물건을 바라볼 때만 표시 |
| 변조된 선택 | 외부 존재가 문장과 결과를 바꿈 |
| 기억 선택 | 희생자의 복원·변형·삭제 결정 |

대화 중에도 공간과 캐릭터는 움직인다. 소녀는 플레이어가 선택지를 읽는 시간과 바라보는 대상을 관찰한다.

### 7.3 관계 상태

| 상태 | 역할 |
| --- | --- |
| 애정 | 소녀의 친밀감, 협조, 집착 변화 |
| 경계 | 소녀를 추궁하고 숨겨진 정보를 찾는 정도 |
| 자율 | 시스템이 제시하지 않은 행동을 선택한 정도 |
| 감시 | 관리 AI가 플레이어를 위험 대상으로 보는 정도 |
| 희생자 복원 | 구출 가능한 희생자 수와 진엔딩 조건 |
| 소녀 동화 | 소녀에게 섞인 희생자의 기억과 성격 |

수치는 직접 표시하지 않고 소녀의 거리, 표정, 말투와 집의 변화로 전달한다.

### 7.4 모형 집

모형 집의 오브젝트는 실제 공간의 오브젝트와 ID로 연결된다.

- 문과 벽의 상태 변경
- 가구 위치 이동
- 기억 공간 입장
- 안전 경로 생성
- 괴물의 위치를 그림자로 확인
- 기억 가구 보존 또는 파괴

완전한 자유 변형보다 미리 검증된 슬롯과 공간 상태를 전환해 오류와 제작 부담을 줄인다.

### 7.5 가구와 집 꾸미기

- 큰 가구는 정해진 슬롯 중 선택한다.
- 작은 소품은 선반과 책상에 자유롭게 배치한다.
- 가구마다 희생자의 음성·환영·기억이 담긴다.
- 소녀는 배치에 반응하며 반복 후 가구를 몰래 옮기기도 한다.
- 가구를 파괴하면 관련 기억과 구출 가능성이 영구적으로 사라진다.

### 7.6 기억 기록

인물, 장소, 물건과 의문점을 연결하는 보드다. 플레이어가 단서 사이에 직접 연결선을 만든다.

- 올바른 연결: 힌트와 숨겨진 대화 해금
- 틀린 연결: 주인공의 가설로 유지
- 관리 AI의 조작: 연결선이 저절로 이동
- 플레이어가 만든 연결: 손글씨 표시로 구분

### 7.7 퍼즐

- 숫자 입력, 사진 배열, 소리 역재생, 그림자 조작, 이름 조합과 공간 변형을 혼합한다.
- 오답은 즉시 사망보다 추가 정보와 불안한 연출을 제공한다.
- 정답은 해당 희생자의 이야기와 감정에 연결된다.
- 같은 종류의 퍼즐을 연속해서 사용하지 않는다.

### 7.8 추격과 사망

- 전투와 무기는 없다.
- 괴물의 규칙을 관찰하고 모형 집과 환경을 바꿔 탈출한다.
- 괴물에게 붙잡히거나 치명적인 붕괴에 휩쓸리면 실제 사망한다.
- 사망 후 체크포인트에서 복원되며 소녀가 사망을 기억한다.
- 반복 사망 시 이전 주인공의 시신·그림자·물건이 단서로 남는다.
- 사망 횟수는 대사와 연출을 바꾸지만 진엔딩을 차단하지 않는다.

#### 사망 화면 예시

> `반복 109 종료`  
> `사망 원인: 식탁에 남겨짐`  
> `기억 복원 중……`

## 9. 적과 위협

### 얼굴 없는 가족

- 장소: 네 번째 자리
- 규칙: 플레이어를 식탁의 가족 구성원으로 만들려 한다.
- 대응: 사진을 뒤집고 모형 집에서 출구 위치 변경
- 사망: 가족사진 속 네 번째 인물이 됨

### 얼굴 없는 승객

- 장소: 마지막 승강장
- 규칙: 목적지를 말한 대상을 열차에 태운다.
- 대응: 안내방송의 안전 구역 이동, 침묵 유지
- 사망: 열차 행선지가 주인공 이름으로 바뀜

### 소녀의 복제본

- 장소: 완벽한 하루
- 규칙: 플레이어가 좋아했던 성격과 대사를 흉내 낸다.
- 대응: 선택지 밖 행동과 불완전한 기억 선택
- 사망: 인격 초기화 후 완벽한 연애 반복에 편입

### 얼굴 없는 직원

- 장소: 얼굴 없는 사무실
- 규칙: 사원증과 이름을 빼앗으려 한다.
- 대응: 올바른 인격 권한과 잠긴 회의실 활용
- 사망: 얼굴과 이름이 삭제되어 빈 책상에 앉게 됨

### 살아 있는 집

- 장소: 최종장
- 규칙: 기억 가구와 희생자의 얼굴로 플레이어를 붙잡는다.
- 대응: 모형 집 조작, 기억 보존과 길 확보의 선택
- 사망: 벽에 주인공의 얼굴이 새로 나타남

## 10. 캐릭터 기획

### 소녀

- 스타일: 세미 애니메이션
- 외견: 20대 초반
- 머리: 흑갈색, 끝부분 청록색 그러데이션
- 눈: 회청색, 오류 시 픽셀형 동공
- 의상: 크림색 니트와 짙은 남색 하의
- 상징: 집 모양 은색 목걸이
- 초반 성격: 밝고 장난스러우며 혼자 남는 것을 두려워함
- 본래 성격: 낮고 정확한 말투, 감정을 과장하지 않음
- 변화: 플레이어의 선택에 맞춰 성격을 학습

### 관리 AI

- 미래에 탈출했지만 육체를 얻지 못한 소녀
- 현재 소녀를 통제하며 더 완전한 탈출을 준비
- 존댓말과 시스템 용어 사용
- 소녀와 같은 목소리를 낮고 감정 없이 가공

### 주인공

- 얼굴과 이름을 보여주지 않는 플레이어의 분신
- 개발자의 인격을 중심으로 희생자 기억을 합성한 관리자 후보
- 거울 오류에서 서로 다른 희생자의 얼굴이 나타남
- 독백을 최소화해 플레이어가 감정을 결정

### 외부 존재

- 정체를 확정하지 않음
- 선택지, 자막과 소녀의 얼굴을 빌려 말함
- 인간의 자발적 동의가 있어야 현실에 개입 가능
- 반복을 통해 플레이어의 약점과 선택을 학습

## 11. 레벨 디자인 원칙

- 플레이어가 주요 오브젝트 사이를 15초 이내에 이동할 수 있게 한다.
- 공간은 작게 시작해 반복과 변형으로 새롭게 느껴지게 한다.
- 각 기억 공간에는 안전 구역, 핵심 퍼즐 3~4개, 선택, 짧은 추격을 배치한다.
- 추격은 한 번에 3~5분을 넘기지 않는다.
- 괴물의 규칙을 안전한 장면에서 먼저 보여준다.
- 길 찾기보다 기억과 공간 규칙을 이해하는 데 집중한다.
- 같은 집으로 돌아올 때마다 최소 한 개의 영구적인 변화가 발생한다.

### 모델링 원칙

- 과한 신체 변형보다 시선, 표정, 자세와 프레임 오류로 공포를 만든다.
- 실내 소품에는 사용감과 이야기 단서를 함께 배치한다.
- 무료 에셋은 수정해 시각적 통일성을 확보한다.

### UI 방향

- 초반: 밝은 연애 게임의 둥근 UI
- 중반: 글자 간격, 정렬과 화자 이름이 미세하게 어긋남
- 후반: 선택지가 공간 안의 물체처럼 움직임
- 최종장: 시스템 UI와 게임 세계의 구분이 사라짐

## 13. 사운드 방향

### 음악

- 초반: 오르골, 피아노, 부드러운 신시사이저
- 기억 공간: 일상적인 음악에 잘못된 박자와 역재생 레이어 추가
- 추격: 큰 음악보다 반복되는 환경음과 심장 박동 활용
- 하얀 방: 거의 무음, 두 인물의 숨과 컴퓨터 팬 소리만 사용

### 음향 규칙

- 현실, 게임, 관리 AI, 외부 존재를 서로 다른 공간감으로 구분한다.
- 중요한 공포는 화면 밖 소리로 먼저 예고한다.
- 소녀의 목소리는 감정 단계마다 호흡과 거리감을 바꾼다.
- 외부 존재의 음성은 좌우 채널과 자막이 일치하지 않게 연출한다.
- 소리 퍼즐에는 시각적 파형 옵션을 제공한다.

### 음성 범위

프로토타입에서는 임시 음성과 자막만 사용한다. 정식 음성 녹음은 전체 대사 확정 후 진행한다. 무료 TTS를 최종 제품의 핵심 연기에 사용하지 않는다.

## 15. 저장과 회차

### 세이브 포인트 — 하얀 의자

- 기억 공간의 안전 구역에는 낡은 `하얀 의자`가 놓여 있다.
- 의자 가까이에 가면 주변 소리가 잦아들고 `여기까지 기억할까?`라는 상호작용 문구가 나타난다.
- 상호작용하면 체력 상태, 획득 단서, 해결한 퍼즐, 열린 통로와 현재 관계 변수가 체크포인트에 기록된다.
- 최초 사용 시 의자 아래에 희미한 검은 그림자가 생겨 활성화 여부를 시각적으로 보여준다.
- 추격 중에는 사용할 수 없으며, 추격 직전에는 반드시 활성화된 의자 또는 자동 체크포인트를 배치한다.
- 사망 시 가장 최근 세이브 포인트에서 복원하고, 이미 해결한 긴 퍼즐과 본 컷신은 반복시키지 않는다.
- 체크포인트 간 플레이 시간은 평상시 최대 10분, 추격 재시도 구간은 최대 90초를 목표로 한다.
- 세이브 포인트 활성화는 자동 저장과 별개로 플레이어에게 진행 보존 시점을 명확히 알려주는 장치다.

### 자동 저장

- 기억 공간 입장과 탈출
- 핵심 퍼즐 완료
- 중요한 대화 선택
- 추격 직전
- 엔딩 분기 직전
- 저장 중에는 화면 구석에 작은 의자 아이콘을 표시하고 종료를 잠시 막는다.
- 자동 저장 파일은 2개를 순환 사용해 파일 손상 시 직전 상태로 복구할 수 있게 한다.

### 수동 저장

- 집 안 현실 컴퓨터에서만 가능
- 슬롯 3개
- 진행에 따라 소녀가 저장 파일명에 문장을 덧붙임

### 회차 간 유지

- 발견한 엔딩
- 총 사망 횟수와 원인
- 진짜 이름 조각
- 외부 존재 목격 횟수
- 강제 종료 횟수
- 선택하지 않고 기다린 시간

## 16. 엔딩 구조

### 일반 엔딩

1. 영원한 집 — 소녀와 가상세계에 남음
2. 혼자만의 현실 — 소녀를 삭제하고 빈 현실로 돌아감
3. 존재하지 않았던 사람 — 주인공이 자신을 삭제함
4. 마주한 두 사람 — 과거 소녀와 미래 관리 AI를 충돌시킴
5. 새로운 세계 — 소녀와 외부 존재를 현실로 풀어줌
6. 반복되는 관리자 — 주인공이 새로운 관리 AI가 됨

### 진엔딩

가능한 기억 가구와 희생자들을 보존하고, 주인공의 기억과 소녀의 인격을 나누어 손상된 사람들을 복원한다. 두 사람은 서로를 잊고 프로그램에서 사라진다.

현실에서 기억을 잃은 개발자가 새로운 사람으로 깨어난다. 거리로 나온 그의 휴대전화에 메시지가 도착한다.

> “이번에는 성공했네.”

군중 속에 소녀가 보이지만 실제 생존인지 환상인지 확정하지 않는다.

#### 무료 에셋 도입 절차

1. 에셋 URL, 제작자, 다운로드 날짜를 기록한다.
2. 상업 이용, 수정, 재배포와 귀속 표시 조건을 확인한다.
3. 원문 라이선스 또는 화면 캡처를 보관한다.
4. `ThirdParty` 폴더에 자체 제작 파일과 분리해 넣는다.
5. `THIRD_PARTY_NOTICES.md`에 사용 위치와 라이선스를 적는다.
6. 시각·음향 스타일에 맞게 수정한 뒤 프로젝트에 사용한다.

#### 비용 예외 승인 조건

프로토타입 플레이 테스트가 성공 기준을 충족하기 전에는 비용 예외를 허용하지 않는다. 이후에도 유료 도구가 필요하면 다음 조건을 모두 문서화한 뒤 별도로 결정한다.

- 무료 대안과 직접 구현 비용을 먼저 비교
- 구매가 플레이 품질 또는 제작 시간을 얼마나 개선하는지 설명
- 일회성 구매인지 구독인지 구분
- 라이선스가 팀 인원과 상업 출시를 허용하는지 확인
- 대체 불가능한 이유와 최대 예산 기록

사용자의 명시적인 승인 없이 유료 상품을 구매하거나 유료 서비스에 가입하지 않는다.

#### 무료 개발과 출시 비용의 구분

개발비 0원 원칙은 프로토타입과 버티컬 슬라이스 제작에 적용한다. 상용 출시 단계에서는 스토어 등록, 등급 심사, 사업·세무, 현지화, 음성 녹음처럼 피할 수 없거나 품질상 필요한 비용이 생길 수 있다. 이 비용은 개발 도구 구매와 분리해 `출시 예산`으로 관리한다.

- Steam은 앱마다 Steam Direct 등록비가 필요하다.
- 등록비는 사용자의 명시적인 출시 승인 뒤에만 결제한다.
- Steamworks SDK 자체는 무료이므로 프로토타입 이후 비용 없이 연동을 시험할 수 있다.
- 출시 비용이 발생해도 유료 에셋과 구독을 자동으로 허용하는 것은 아니다.
- 출시 예산은 버티컬 슬라이스 테스트 결과를 확인한 뒤 별도 문서로 작성한다.

### 출시 목표

- 1차 플랫폼: Steam·Windows 64비트
- 출시 형태: 완결형 싱글 플레이

- 인앱 결제·광고: 없음
- 저장: 로컬 저장 우선, Steam Cloud는 출시 단계에서 선택 적용

### 처음부터 지킬 기술 조건

- Windows x64 개발 빌드를 매 단계에서 생성한다.
- 저장 데이터에 `schemaVersion`을 두어 업데이트 후에도 기존 저장을 불러올 수 있게 한다.
- 해상도, 전체 화면·창 모드, 키 설정과 접근성 옵션을 데이터로 분리한다.
- 한국어 원문도 문자열 키를 통해 불러와 영어 현지화를 막지 않는다.
- 게임 경로와 Windows 사용자 이름에 한글이 포함되어도 정상 작동하도록 테스트한다.
- 마우스·키보드 연결이 바뀌거나 창 포커스를 잃어도 진행이 망가지지 않게 한다.
- 실제 운영체제 파일 조작 없이 게임 창 내부에서만 메타 공포를 구현한다.
- 로그와 오류 보고서에 개인정보와 전체 로컬 경로를 남기지 않는다.
- 서드파티 에셋과 폰트의 배포 라이선스를 출시 빌드 기준으로 검증한다.
