# Stage 15 환경 최소 디자인 QA

## 목적

`04_StoryRoute`의 여덟 방이 기능 검증용 회색 박스 모음이 아니라, 플레이어가 장의 장소와 핵심 사건을 화면만 보고 구분할 수 있는 최소 환경 디자인을 갖추는지 검증한다. RealityRoom의 최종 미술 품질과 동일함을 요구하지는 않지만, 디버그 골격이 플레이 화면의 주인공이 되는 상태는 허용하지 않는다.

## 자동 계약

- 각 방은 고유한 벽·천장, 입구·목표 조명, 장소를 설명하는 구조물, 가구 또는 생활 소품, 인물이나 사건의 핵심 실루엣을 각각 포함한다.
- 프롤로그는 인형집·소파·유나, 1장은 식탁·빈 의자·가족 사진, 2장은 승강장·막차·얼굴 없는 승객, 3장은 카페·공원 벤치·반복 인물, 4장은 창문 없는 사무실·책상·동일 얼굴 직원, 5장은 묘지·장례식장·얼굴 없는 조문객, 6장은 축소 도시·모니터·플레이어 뒷모습, 최종장은 살아 있는 집·하얀 방 의자·희생자 얼굴을 최소 정체성으로 사용한다.
- `Debug`, `Placeholder`, `Story Action` 같은 구현용 이름의 오브젝트가 플레이 장면에 남지 않는다.
- Beacon·Highlight는 안내 보조물이다. 충돌체가 플레이어를 막아서는 안 되며 Beacon은 작은 강조점으로 유지한다. 화면을 어지럽히던 `Route Room N Path` 바닥 표식은 제거 상태를 유지하고 월드 텍스트는 방 전체를 덮는 간판 크기가 되어서는 안 된다.
- 150개 액션 오브젝트는 활성 상호작용 Collider를 가지되 유나를 제외하고 중앙 통로 바깥에 배치한다. 별도 바닥 화살표 없이 조명·의미 소품·목표 문구로 다음 행동을 찾을 수 있어야 한다.
- 여덟 방의 바닥 팔레트는 서로 달라야 하며, 같은 방에서도 바닥과 벽이 하나의 회색 면처럼 합쳐지지 않아야 한다. 목표 조명은 입구 주변광보다 강한 시각 계층을 갖는다.

자동 fixture는 `Stage15EnvironmentMinimumDesignAcceptanceTests`이며 기존 `Stage15VisualPresentationAcceptanceTests`의 유나·표지·150개 연결·우회 차단 계약을 보완한다.

## 720p / 1080p 수동 구도 점검

1280×720과 1920×1080에서 각 방 Arrival로 이동한 뒤 아래를 반복한다.

| 확인 항목 | 합격 기준 |
|---|---|
| 첫 화면 장소 인식 | 3초 안에 방 이름 표지와 장별 핵심 구조물 하나가 함께 보인다. 다른 방 골격은 보이지 않는다. |
| 중앙 동선 | 전진 시 상자·프레임·화살표가 길을 막지 않고 첫 액션까지 우회 없이 이동한다. |
| 액션 발견 | 목표 조명과 작은 강조점이 의미 소품을 보조한다. 발광 프레임 자체가 소품보다 크게 읽히지 않는다. |
| 월드 텍스트 | 표지가 화면 밖으로 잘리거나 거울상으로 보이지 않고, 유나·소품·HUD와 중첩되지 않는다. |
| 깊이와 대비 | 바닥·벽·천장 경계가 구분되고 핵심 실루엣이 배경에 묻히지 않는다. 완전 암부나 균일한 회색 화면이 없다. |
| 생활감 | 장소별 가구나 생활 소품이 최소 2종 보이고, 의미 없는 동일 큐브 반복이 주 시야의 절반 이상을 차지하지 않는다. |
| UI 동시 표시 | 목표 HUD·조사 Prompt·Pause가 핵심 오브젝트와 표지를 동시에 모두 가리지 않는다. |

## 현재 한계와 후속 기준

이 계약은 자체 Primitive로 만든 블록아웃의 최소 합격선이다. 캐릭터 모델, 텍스처, 소리, 애니메이션과 실제 퍼즐 조작 연출을 완성한 것으로 간주하지 않는다. 수동 화면에서 의미 소품보다 큐브·발광 프레임이 먼저 읽히면 자동 테스트 통과와 무관하게 시각 QA 실패로 기록한다.

외부 에셋과 추가 라이선스는 사용하지 않는다.
