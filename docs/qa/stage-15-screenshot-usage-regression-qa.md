# Stage 15 스크린샷 실사용 회귀 QA

## 실패 계약

최신 사용자 플레이 스크린샷에서 드러난 문제를 다음 승인 게이트로 고정한다.

- 문짝·문틀·조사 Collider가 같은 위치와 높이를 사용한다. 문틀은 좌우 대칭이고 상인방이 중앙에 있으며 문을 보면서 다른 위치를 조사하는 상태가 없어야 한다.
- 월드 공간명과 발광 프레임은 보조 안내다. Arrival 첫 화면에서 표지는 화면 폭 55%·높이 30%, 단일 강조 프레임은 폭·높이 38%를 넘지 않는다.
- 저장 모달은 1280×720과 1920×1080 전체 화면을 dim/raycast로 소유하여 gameplay HUD, 조사 Prompt, 퍼즐 UI가 읽히거나 눌리지 않게 한다. 세 슬롯마다 저장 시각·장소·현재 장/진행을 표시하고 저장 성공·실패 이유를 즉시 보여준다.
- 진행 전 기록의 빈 상태는 허용하지만 첫 행동 이후 Tab 기록은 비어 있으면 안 된다. 현재 장, 완료/현재 행동, 다음 목표가 한 화면에 표시되어야 한다.
- 모든 조사 행동은 한글 `[E]` 의미 문구가 있고 성공·잠김 뒤 다음 행동 또는 다음 마커를 알려야 한다.

## 자동 연결

`Stage15ScreenshotUsageAcceptanceTests`가 문 구조/Collider 정렬, 두 해상도 월드 안내물 점유율, 저장 전체화면 blocker·피드백·3개 슬롯 메타, StoryRoute 기록 진행 요약, 150개 행동 프롬프트를 검증한다. 기존 `Stage10IntegrationTests`와 StoryProgress roundtrip fixture는 실제 데이터 보존을, `InteractionPromptLifecyclePlayModeTests`는 StoryRoute 진입/비활성화의 exception 0을 담당한다.

## 1280×720 / 1920×1080 수동 스모크

| 흐름 | 조작 | 합격 기준 |
|---|---|---|
| 문 조사 | 모든 문 정면·측면에서 접근 후 E | 문짝과 프롬프트 대상이 일치하고 문틀 밖 허공에서 조사되지 않음 |
| 첫 화면 | 각 방 Arrival에서 정지 | 월드 텍스트·프레임이 화면을 지배하거나 서로/HUD와 겹치지 않음 |
| 다음 행동 | 정순·오순서 행동 각각 수행 | 성공/잠김 사유와 다음 목표가 4초 이상 읽히고 실제 다음 오브젝트를 찾을 수 있음 |
| 기록 | 첫 행동 전 Tab, 행동 1·중간·장 완료 후 Tab | 빈 상태는 최초만, 이후 장/행동/다음 목표가 갱신되며 긴 한글이 잘리지 않음 |
| 저장 표시 | 퍼즐 직전 저장 열기, 세 슬롯 저장, 실패 조건 유도 | 모달 밖 gameplay/puzzle이 완전히 가려지고 슬롯 시각·장소·진행·결과가 갱신됨 |
| 저장 왕복 | 중간 행동 저장→다른 행동→불러오기 | 저장 시점 장/행동/다음 목표와 기록이 복원되고 중복 행동이 없음 |
| 입력 소유 | 저장 중 E/Tab/Esc/이동/클릭 | 슬롯 조작과 저장 닫기 외 하위 입력이 실행되지 않음 |
| 로그 | RealityRoom→StoryRoute→저장 왕복 후 종료 | Player.log의 Exception, NullReference, coroutine 오류가 0건 |

실제 Windows 저장 왕복과 Player.log 확인 없이 스크린샷 수정만으로 승인하지 않는다. 외부 에셋과 추가 라이선스는 사용하지 않는다.
